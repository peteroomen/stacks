# Audit — bugs, pipeline, UI/UX polish, roadmap

Full-app audit pass. Everything in "Changes made" ships in one PR; "Roadmap"
is the suggestion list, nothing there is implemented.

## Bugs found & fixed

1. **`link_plays_to_tracks` RPC was broken** (`0004_link_plays.sql`): `plays.id`
   is `bigint`, but the pair's play id was cast with `::uuid` — every call failed
   at runtime ("invalid input syntax for type uuid"), so
   `scripts/attribute_track_plays.mjs` could never link plays. Fixed in
   migration `0005` (needs `supabase db push`).
2. **Library search broke on `, ( )`** — the free-text `q` was interpolated raw
   into PostgREST `.or()` filter syntax, where those characters are structural.
   Searching `(What's the Story) Morning Glory?` returned a silent 400/empty.
   Values are now double-quoted and quote characters stripped.
3. **ListenBrainz ingest silently dropped plays** — the API clamps `count` to
   100 (we asked for 200), there was no pagination and no `min_ts`, so anything
   past the newest 100 listens between cron runs was lost. Now resumes from the
   newest stored listen and pages forward (up to 500/run).
4. **Cron endpoints were open when `CRON_SECRET` was unset** — the check was
   `if (CRON_SECRET && ...)`, i.e. fail-open. Both cron routes now fail closed.
5. **`rollup_play` could double-count** if re-invoked for a play that was
   already attributed; it now skips plays with `album_id` set. It also now
   attributes the play to a **track** (normalized-title match) and bumps
   `tracks.play_count`, so scrobbles keep per-track counts fresh (previously
   only the one-off backfill script did this).
6. **Auth-callback failures were invisible** — callback redirects to
   `/login?error=auth` but the login page never read it. Now shown.
7. **Rate deck advanced past failed saves** — a failed PATCH still counted the
   album as rated and moved on. Now surfaces the error and stays put.
8. **Rating histogram silently dropped ratings < 4** (hardcoded 4–10 buckets).
   Buckets now extend down to the lowest actual rating.
9. **Unvalidated PATCH bodies** — `/api/albums` and `/api/tracks` now
   zod-validate (uuid id, rating 0–10, bounded strings). Previously a bad
   payload surfaced as a raw Postgres error.
10. **Insights upsert errors were swallowed** — a failed cache write returned
    200 with stale data. Now a 500.
11. **Biased shuffle** in the digest's comment sample
    (`sort(() => Math.random() - 0.5)`) → Fisher–Yates.

## UI/UX changes

- **Search debounced** (300 ms) — was one request per keystroke.
- **Error + empty states everywhere**: library fetch failure (with retry), no
  filter matches (with reset), album/track save failures, insight refresh
  failures, chat errors (with retry). All were previously silent.
- **Sortable table headers** (Artist / Year / Rating / Plays) in table view.
- **Chat**: auto-scrolls during streaming, example prompts are clickable,
  assistant line breaks render (`whitespace-pre-wrap`).
- **Insights**: shows "Updated Nh ago" so you know how stale the cards are.
- **Rate deck**: ← back button + ArrowLeft key to revisit the previous card.
- **Dashboard**: time-of-day greeting (was hardcoded "Good evening"); new
  **Recently played** strip from the plays timeline — each cover deep-links to
  YouTube Music.
- **Escape closes the album drawer** (first Esc blurs a focused field).
- **Lazy-loaded cover images** in grid/table (48 covers per page otherwise all
  load eagerly).
- **Favicon**: the wordmark's green vinyl record (`src/app/icon.svg`).
- Pagination scrolls back to the top of the list on page change.

## Deploy notes for this PR

- Run `supabase db push` (applies `0005_fix_link_plays_and_track_rollup.sql`).
- Ensure `CRON_SECRET` is set in Vercel — cron routes now 401 without it.
- Re-run `node --env-file=.env.local scripts/attribute_track_plays.mjs` once if
  you want historical plays linked (the RPC it depends on was broken until now).

## Pipeline observations (not changed)

- `enrich_covers.mjs` and `/api/enrich/covers` duplicate the MB/CAA/Deezer/iTunes
  logic (~100 lines). Tolerable for now; extract to a shared module if it grows.
- `import_takeout.mjs` **replaces** `listen_count` for matched albums with the
  sessionized YT count — by design, but destructive; noted here so future-you
  remembers.
- Take care: `listen_count` has two semantics — sessionized *spins* from the
  Takeout import vs +1 *per track scrobble* from ListenBrainz. See roadmap.

## Roadmap / feature ideas

**High value, low effort**
1. **Sessionize ListenBrainz rollup** — count album *spins* (session of ≥3
   distinct tracks, like the Takeout importer) instead of +1 per track play, so
   `listen_count` means one thing. Could run as a daily reconciliation query.
2. **Re-link job for orphan plays** — plays with `album_id IS NULL` are never
   retried, so albums added after the fact never claim their history. A small
   cron/RPC that re-runs matching over orphans would fix that (and would have
   the new track attribution for free).
3. **URL-synced library filters** — put filters/page in the query string so
   browser back works and views are shareable/bookmarkable.
4. **Genre drill-down** — click a bar on the dashboard genre chart → library
   filtered to that parent genre (easy once filters live in the URL).
5. **CSV export** — the "data is never trapped" promise. One route, one button.

**Medium**
6. **Listening timeline page** — plays-per-week chart, per-album play history
   in the drawer ("you spun this 9× in March 2024"), top artists by period.
   The `plays` table already has everything.
7. **Search includes track titles** — "which album has that song on it" is a
   real lookup; `tracks` is already there.
8. **Random spin picker** — "play me something": weighted random from
   high-rated + not-recently-played. One button on the dashboard.
9. **Wrapped** — LLM year-in-review from plays + ratings (the original roadmap
   item; the digest pattern extends naturally).
10. **PWA manifest** — home-screen install for phone rating sessions.

**Later**
11. **MBID-based matching** — plays carry `recording_mbid`/`release_mbid`;
    matching on those (when present) beats string equality and kills most of
    the edition/remaster fuzz.
12. **Insight cards → deep links** — "revisit" items could link to the album
    drawer / YT Music directly.
13. **Multi-window insight cache** — keep a history of generated insights so
    "what did it say last month" is answerable (cheap: drop the unique
    constraint, add `generated_at` to the key, show latest).
